# Design

Hi-fi user flows: `docs/design/flows.html` (21 screens). The bank as the student sees it:
`docs/design/questions.html`. Both share `app.css` (tokens and components), `flows.css` (viewer and test pieces),
`icons.js` and `figures.js`.

## Look

One system for the mini app and the website.

- **Type.** Merriweather Light 300 for display and headings (−0.025 em tracking, line-height ≈ 1); Merriweather 400 for
  question text and body; Carlito 700 uppercase 12–13 px for kickers, metadata and labels (`.kicker`, `.meta`);
  Carlito 700 16–19 px for card titles. Carlito has Cyrillic, so the RU build needs no extra font.
- **Colour.** Tokens in `app.css`, two themes (`.screen` / `.desk` default = day, `.theme-night`):
  `--bg --ink --muted --faint --band --line --tag-line --accent --on-accent --sel-bg --sel-ink --danger`.
  One accent blue (`#0290d7` day, `#35b0f2` night). Black fills mean "selected" or "done" (`--sel-bg`).
  Red is only for wrong, danger and the fail state; yellow only for flags and buoys. There is no green in the
  UI — a correct answer is accent blue with a check mark, so it does not depend on colour alone.
- **Shape.** Bands and cards 20–28 px radius (squircle where supported), pills 54 px, 2 px outlines in
  `--tag-line`, selected outline in `--ink`.
- **Phone chrome.** 390 × 844, iOS status bar, Telegram mini-app header (`.tgh`) and main button (`.tgmain .b`),
  bottom tab bar (`.nav`) on the five root screens only (Learn, Theory, Exam, Progress, Profile).
- **Website.** 1280 wide desk, 1180 wrap, 76 px header with the RYC logo + "IYT Test" wordmark, nav, language
  switch, "Open in Telegram" pill; display 60 px in the hero; footer carries the disclaimer once.

**B · Mini app · Mock exam** — B1 Intro (40 / 60 min / 70 %, rules, last attempts) · B2 Exam question (timer,

**T · Mini app · Theory** (added 2026-11-05, not in flows.html yet) — T1 Theory, the second tab (chips to change the

**C · Mini app · Progress, profile, bot** — C1 Progress (stats, week, mastery by topic, mistakes) · C2 Profile

**D · Website** — D1 Landing (hero with a live sample question, four level cards, how it works, theory band) ·
D2 Level page (topics with mastery, rotating sample, sticky box with Practise / Mock exam) · D3 Question at desktop

## Rules of the screens

- A question screen shows one question; the figure, if any, sits between the topic chip and the question text;
  the Telegram main button is the only "Check"/"Next" and is grey until an option is chosen.
- Practice gives the verdict and the one-line note after every answer; the exam gives nothing until submit.
- Wrong answers go to the mistakes list and come back until answered right twice (mastery).
- The next useful step is always the main button on a result screen (practise the weakest topic, review mistakes).
- No promo on questions. The one band (theory notes / next level) appears on home, profile, level page, passed result.
- Everything that lists topics (level page, progress, set-up chips, result bars, website rail) is the same component
  fed by the same topic list (`TOPICS` in `flows.js` for the mock-ups; the `topics` table in the app).

## The viewer

`flows.html` has two modes: **Pages** (index · one screen scaled to fit · notes with the caption, ← → to turn,
`#A4` links) and **Overview** (every lane with captions, for a read-through). **Day / Night** switches the screens'
theme and the viewer's own. State is remembered in localStorage. The index and notes are built from each `.art`'s
`data-id` and `.cap` text, so adding a screen is adding an `.art` block inside a `section.flow` (with
`data-who="app|web|bot"`).

`questions.html` lists the bank: filter chips per topic, each card with id, topic, difficulty dots, figure, options
with the right one marked, the note and the reference. It fetches `../../data/questions/bareboat-skipper.json`
(or `bareboat-skipper.json` beside it when published), so serve the folder over HTTP.

## Icons

`test-icons.js` is the app's own set: 24 grid, 2 px stroke, round caps and joins, 2 px clear of the edges — the same
hand as the figures. `icons.html` is the sheet (every glyph at 24 px and at 18 px in the topic circle; `?size=72`
to inspect a construction; the day / night button switches the theme). The set has three parts:

- the app: tabs (book, timer, chart, user), buttons (play, next, back, check, x, refresh, share), exam (flag, grid,
  trophy), streak (fire), theme (sun, moon), language (globe);
- the boat, safety, rules and navigation, weather, radio: one glyph per topic of every level — yacht, sail, wheel,
  propeller, gear, cleat, knot, anchor; lifebuoy, lifejacket, medkit, flare, binoculars, captain, mug; rules
  (the give-way arrow), dividers, compass, map, buoy, lighthouse; wind, cloud, barometer; vhf, radio, mic,
  flag-alpha, mmsi, megaphone, beacon, licence;
- old names (ring, rope, light, wrench, board-view) kept as aliases so banks saved before the set keep working.

Which topic gets which glyph is `TOPIC_ICONS` in `miniapp/app.js` (per level) and the icon column of
`data/build_level.py` (the banks carry the same names). Use `<span data-i="name" data-s="18"></span>`;
`paintIcons()` fills them; `svg(name, size)` returns the markup. A few basic glyphs follow Lucide (ISC — see
`LICENSE-lucide.txt`); `icons.js` is the older base set the viewer still loads first for the Telegram chrome in the
mockups (dots, clip, status).
